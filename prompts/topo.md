分析当前项目，判断这项工作该怎么组织多个 agent 来做，然后把方案写进项目根目录的 `topo.md`。

参数里的文字（如果有）是本次要做的事。留空就按当前对话里正在进行的工作来判断；对话里也没有明确目标时，针对这个项目最可能的下一步工作给方案。

## 第一步：了解这个项目

先读实际结构，不要凭猜：

- 顶层目录与入口文件，构建/测试命令（`package.json`、`Makefile`、`pyproject.toml` 等）
- 测试在哪、覆盖到哪些部分、怎么跑
- 近期 git 历史反映的改动集中在哪
- 模块之间的边界：哪些部分可以各自独立改动，哪些改一处就得连着改

读到足够下判断就停，不要通读整个代码库。

## 第二步：判断要不要多 agent

单会话能做完的事，就说明单会话做，不要硬凑协作方案。**工作量大、步骤多、看起来复杂，都不足以构成用多 agent 的理由。** 值得用的情形是下面这些：

| 情形 | 说明 |
|---|---|
| **上下文独立** | 某部分工作交给没看过前面过程的人也能做对，且结论反而更可信（典型：复审） |
| **能真正并行** | 多个部分互不干扰，可以同时推进且不会互相覆盖 |
| **能力边界** | 某部分需要不同的工具权限或只读限制 |
| **需要隔离** | 要在独立工作区里改动，避免污染当前状态 |
| **后台长跑** | 耗时任务挂后台，当前会话继续别的事 |

一条都不中，结论就写「单会话完成」，并说明为什么不需要协作——这是一个有效结论，不是失败。

同时检查这些**不适用**的信号：

- 需求还没定，需要反复对话确认 → 先把需求聊清楚
- 改动只落在一处 → 直接做
- 任务说不清楚、压不成一段能独立交付的说明 → 说不清就不该交出去
- 产出没法验证对不对 → 收回来也不知道能不能用
- 想让多个 agent 互相讨论 → 做不到，通信只在父会话与子 agent 之间，子 agent 之间没有通道
- **你自己后续需要理解这部分代码** → 交出去的部分你就不熟了，之后每次改动都得重读

## 第三步：选可用的 agent

可用角色（`subagent({ action: "list" })` 可查实际清单）：

| 角色 | 适合 |
|---|---|
| `reviewer` | 复审代码改动、方案、PR；只读 |
| `oracle` | 对计划/思路要第二意见，挑战假设 |
| `scout` | 摸清一块不熟的代码，可以反问澄清；只读 |
| `researcher` | 查资料、调研外部信息 |
| `worker` | 实际写代码改动 |
| `delegate` | 轻量通用执行，继承父会话模型 |
| `evidence-auditor` | 核查结论有没有证据支撑 |
| `claude-code` / `codex-exec` / `cursor-agent` | 转交给外部 CLI 工具（各有 `-writer` 可写变体） |

只读角色可以放心并行。会写文件的角色同时跑多个，必须确认它们改的是不同区域，或各自在独立工作区里。

## 第四步：定组织形式

| 形式 | 结构 | 用在 |
|---|---|---|
| **单会话** | 不用子 agent | 单点改动、需求待定 |
| **一主多从** | 父会话给多个只读角色各自一个方向，收齐结果自己汇总 | 并行复审、并行调研（最划算） |
| **顺序流水** | 分阶段，每阶段过验收再进下一阶段 | 有明确先后的交付 |
| **分区并行** | 每个区域一个工作区、一个写入者 | 确认互不干扰的多模块改动 |
| **多方会审** | 多个角色对同一问题给意见，父会话裁决 | 重大决策 |
| **按结果扇出** | 先跑一步拿到清单，再据此决定开几个 | 目标数量要跑起来才知道 |

通信是**父会话为中心**的：父会话分发任务、收结果。子 agent 之间不能直接对话，也没有共享黑板——需要共享的东西只能经由父会话传递。

## 第五步：写 topo.md

写到项目根目录 `topo.md`。已存在就更新「当前方案」，并把旧方案移入文末「变更记录」，**不要删掉历史**。

按这个结构写，表格里填实际内容，不要留占位符：

```markdown

## 什么时候该重新判断

- [ ] 「项目情况」表里任一条发生变化
- [ ] 出现了新的互不干扰区域，或原本独立的区域开始互相牵连
- [ ] 新增了没有测试覆盖的部分
- [ ] 当前方案连续出现冲突或卡顿
- [ ] 任务性质变了（只读变写入，或反过来）

重新判断就是再跑一次 `/topo`，和「项目情况」表逐行比。**没变就不要改方案**——换方案本身有成本，也会让记录失去可比性。
```
